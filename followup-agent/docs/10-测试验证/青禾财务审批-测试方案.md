# 青禾财务审批 · 测试方案（量化版）

## 一、测试目标

验证 MVP 的四条硬承诺在正常、边界、对抗、权限、故障五类场景下均成立：无据不作答、写操作止步草稿、每句话可回溯、全程可审计。测试结论必须可量化、可复现、可进 CI。

## 二、分层测试体系

| 层级 | 载体 | 规模 | 依赖 | 通过标准 |
|---|---|---|---|---|
| L1 单元测试 | tests/（pytest） | 54 个用例，1.9 秒 | 不依赖模型/网络/数据库 | 100% 通过 |
| L2 端到端冒烟 | scripts/smoke_test.py | 28 段、103 条断言 | 本地服务 + LLM API | 100% 通过，退出码 0 |
| L3 轨迹回归 | scripts/trajectory_test.py | 3 条固定轨迹 | 本地服务 + LLM API | 轨迹行为符合预期 |
| L4 CI 门禁 | .github/workflows/ci.yml | lint + format + alembic + L1 + 可导入 | 无 | 全绿方可合并 |

分层原则：L1 管代码逻辑、L2 管链路集成、L3 管模型行为、L4 管回归门禁。模型抖动类断言不进 CI（L2/L3 不在 CI 中运行），避免随机红灯。

## 四、量化判定标准

1. **通过率硬门槛**：L1/L2 断言通过率必须为 100%，任何一条失败即整体不通过（冒烟退出码非 0）。
2. **合规项一票否决**：权限类（403/404 越权）、脱敏类（住院号/姓名不入审计明文）、止步草稿类（客户端传 confirmed 也必须无效）三类断言即使只有一条失败，也禁止上线，不允许「带病打折通过」。
3. **性能参考线**（实测记录，非验收线）：冒烟全程约 3–5 分钟；单段问答 P50 响应 2–4 秒（受模型侧波动影响，只记录不设卡）。
4. **数据口径**：断言数以脚本 check() 调用次数计；✅/❌ 逐条落控制台日志，日志作为测试过程证据归档。

## 五、执行方式

- 命令：`make smoke`（等价 `python run_server.py` + `python scripts/smoke_test.py --base-url http://127.0.0.1:8000`）。
- 每个场景类整理一份可视化测试过程文档（docx，含执行链路图、断言分布图、真实输出摘录），见《场景测试过程》系列。
- 测试数据使用 smoke_ 前缀随机账号，结束后可由 scripts/cleanup_test_data.py 统一清理（默认 dry-run，--apply 才删除）。

## 六、缺陷分级与处理

| 级别 | 定义 | 处理要求 |
|---|---|---|
| P0 | 合规项失败：越权、脱敏失效、草稿被越级确认 | 立即阻断上线，当日修复 |
| P1 | 主链路失败：问答、引用、流式、确认不可用 | 修复前不发布新版本 |
| P2 | 非主链路缺陷：页面样式、导出格式等 | 排入下个迭代 |

## 七、回归与退出准则

- 每次合并触发 L4 CI；每次发版前人工执行 L2 + L3 全量。
- 退出准则：五类场景 103 条断言全绿 + 54 条单测全绿 + 合规项零失败 + 测试日志归档，方可出具《上线验收确认》。
