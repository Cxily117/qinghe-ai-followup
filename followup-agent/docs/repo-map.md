# 仓库地图与汇报口径

> 用途：别人问「你用了什么」「这些文件都是干什么的」「数据哪来的」时，照着这份念即可。
> 维护约定：新增模块时同步更新本文；本文只描述"是什么/为什么"，不复述代码细节。

## 一、一句话定位

清禾医院骨科术后随访智能体：医护用自然语言查制度、查患者、生成随访计划。
三条硬规矩——**答案必须落在已发布的制度条文上**（无据不作答）、**写操作止步于草稿**（人工确认才生效）、**全程留痕可回放**。

## 二、技术栈（被问"你用什么做的"）

| 层 | 选型 | 为什么 |
|---|---|---|
| 语言/框架 | Python 3.13 + FastAPI 0.162 + Uvicorn | 异步 IO 适合"等模型返回"这种长耗时请求；自动生成 OpenAPI 文档便于对接 HIS |
| 数据访问 | SQLAlchemy 2.1（异步） | 同一套模型可跑 SQLite 与 PostgreSQL，不锁死部署形态 |
| 数据库 | 当前 SQLite（`dev.db`）；生产 PostgreSQL 16 + pgvector（`docker-compose.yml` 已给） | 演示零依赖；生产要向量索引与并发 |
| 迁移 | Alembic（5 个版本 0001–0005） | 表结构可回滚，不是靠 `create_all` 蒙 |
| 认证 | JWT(HS256) + PBKDF2-SHA256（26 万次迭代）+ HttpOnly Cookie | Cookie 是为了绕开"网关改写 Authorization 头"这个真实故障 |
| 大模型 | **智谱 GLM**：`glm-4-flash` 对话 + `embedding-3`（1024 维） | 见第三节 |
| 检索 | 混合检索：BM25（jieba 分词）+ 向量余弦，`alpha=0.5`，`top_k=3` | 中文制度里"专有名词精确匹配"和"语义相近"各占一半，单靠一种会漏 |
| 前端 | 原生 JS + 单页 HTML（无构建链）；后台 Jinja2 服务端渲染 | 医院内网环境不值得引入 Node 工具链 |
| 部署 | 单进程 uvicorn（`run_server.py` 读 `PORT`/绑 `0.0.0.0`），PWA manifest | 平台托管只暴露一个端口 |

## 三、模型：是智谱，而且是"可替换的智谱"

`.env` 里三行决定了这件事：

```ini
LLM_PROVIDER=openai                                  # 指的是"OpenAI 兼容协议"，不是 OpenAI 公司
LLM_API_BASE=https://open.bigmodel.cn/api/paas/v4    # 智谱开放平台
LLM_CHAT_MODEL=glm-4-flash                           # 对话模型
EMBED_MODEL=embedding-3                              # 向量模型，显式取 1024 维对齐库表
```

- **为什么写 `openai`**：智谱、DeepSeek、通义、本地 vLLM 都提供 OpenAI 兼容接口，所以代码里只有一个 `OpenAICompatibleProvider`，换供应商只改环境变量，不改一行代码。
- **换模型要做的事**：`LLM_API_BASE` / `LLM_API_KEY` / `LLM_CHAT_MODEL` 三个值 + `scripts/check_llm.py` 验证。
- **为什么用 flash**：制度问答要的是"照条文念"，不是文采；flash 便宜、延迟低（实测 851ms），单条 token 成本低一个数量级。要更强可换 `glm-4-plus`，代码不变。
- **embedding 必须和库表对齐**：`EMBED_DIM=1024` 是硬约束，换模型必须重跑 `scripts/reindex_embeddings.py`，否则检索全错。

汇报口径："表结构是迁移出来的，不是手搓的，能回滚也能审计变更。"

## 五、两条主链路（被问"它到底怎么工作的"）

**标准问答**：登录 → 问题进来 → 混合检索取 top3 → 拼提示词（含"无据必须拒答"）→ 调 GLM → 输出护栏（拒答判定 / 医疗建议拦截 / 来源列表清理 / 引用挂载）→ 落库并审计。

**智能体**：问题进来 → 模型在预置工具骨架内决策（查患者 / 查制度 / 算节点 / 建草稿）→ 每步工具调用都脱敏后入审计 → 涉及写操作时先发**校验票据**（5 分钟、绑患者）→ 生成草稿 → **等人工确认**（10 分钟有效）→ 确认后才落任务。

两个链路的差别可以一句话说清：**问答只读，智能体会动手，但动手前要票据、动手后要签字。**

## 六、数据从哪来（被问"数据真实吗"）

| 数据 | 存在哪 | 真实度 |
|---|---|---|
| 患者 | `patients` 表（`app/agents/data/patients.json` 仅作首次播种） | **演示数据**，`source=seed` 字段可见；接 HIS/EMPI 只需替换同步任务 |
| 制度 | `kb_documents` + `kb_chunks`（12 篇，3 篇已发布） | 演示制度文本，须经护理部审核后发布才算数 |
| 提示词 | `prompt_templates` 版本表（当前 `policy_qa` v25） | 真实配置，可在后台改、可回滚 |
| 账号 | `users` 表 | 演示账号，测试号已清理 |

回答口径："系统里没有任何真实患者数据，`source` 字段写着来源。接真实数据要过三道门：接口对接、制度审核发布、安全加固。"

## 七、汇报三句话

1. **它解决什么**：护士问制度不用翻文件夹，问患者不用切三个系统，答案带条文出处。
2. **它凭什么可信**：无据拒答、引用可点开原文、写操作要人工确认、每一步都有审计。
3. **它现在到哪一步**：功能闭环的 MVP，能用真模型跑通全链路；没有真实数据、没接院内通知、只覆盖两个病种。

## 八、五个常见追问

| 追问 | 回答 |
|---|---|
| 「会不会胡说？」 | 检索不到就固定话术拒答且不调模型；回答必须带 `[n]` 编号，编号能点开原文；模型自己写的"参考资料"列表会被删掉。冒烟里有专门的越界/无据用例。 |
| 「会不会自己改数据？」 | 写操作只能产出草稿，且需要 5 分钟内、绑定该患者的校验票据，再由人点确认。代码里没有任何"直接写入正式任务"的路径。 |
| 「患者信息泄露怎么办？」 | 审计入参脱敏（住院号只留前两位）、结果只存摘要；回答里住院号也是掩码。**但**会话原文表仍存原问题，这是已知待修项（S2）。 |
| 「模型是哪家的，数据会不会出境？」 | 智谱 GLM，境内服务。若要求全内网，改 `LLM_API_BASE` 指向院内 vLLM，代码不变。 |
| 「能不能马上上线？」 | 不能。5 项安全阻断里已修 2 项（默认密钥、零限流），还剩日志保留策略、PHI 原文落库、恢复演练，需要院方配合定策略。 |

## 九、明确不承诺的五件事

1. 没有真实患者数据，不能当生产库用。
2. 未接院内通知（短信/微信/电话），升级工单只生成编号。
3. 只覆盖骨科（髋/膝关节置换）与冠心病两个病种，其他科室答不出来是设计如此。
4. 模型会犯错，所以才有护栏、票据、人工确认——但不能承诺 100% 正确。
5. 单实例部署，没有做多副本与压测，不能承诺高并发。
