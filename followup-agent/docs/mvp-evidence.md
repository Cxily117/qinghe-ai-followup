# MVP 验收单：怎么证明这是能用的 MVP

> 给谁看：想看成果但没时间听讲解的人（医务处、信息科、评审、投资/合作方）。
> 一句话结论：**这不是 PPT，是一个跑得起来、验得出来、边界写得清楚的系统。**
> 你可以让对方自己动手，按下面「三分钟自证」走一遍。

---

## 一、三分钟自证（对方自己就能跑）

```bash
# ① 环境和模型是真的通的（不是写死的假数据）
python scripts/check_llm.py
#   输出：配置就位 / chat 探活（含延迟与 token 用量）/ embedding 维度校验

# ② 库结构和数据是真的
python -m alembic upgrade head          # 14 张表，含用户、知识库、随访草稿、审计、患者目录
sqlite3 dev.db "select count(*) from patients"     # 4 条演示患者

# ③ 功能是真的（29 段 / 99 条断言，全部通过才算过）
python run_server.py &                  # 另开一个终端
python scripts/smoke_test.py            # 末行：全部通过 ✅
```

`smoke_test.py` 不是"能打开页面"的测试，它按业务链路逐条断言，例如：

- 注册接口带 `role=admin` → **422 拒绝**（不能自注册管理员）
- 制度文档不发布 → 提问**不命中**；发布后 → 命中并带引用；归档后 → 又命中不到
- 智能体的写操作**确认前库里没有草稿**，确认后才出现且状态是 `draft`
- 回放他人 run → **404**（不暴露存在性）
- 质控报表 `days=9999` → **422**（窗口参数钳制）
- 医护调管理员接口 → **403**

## 二、证据矩阵：每一句承诺，都有一个能点开的地方

| 承诺 | 在哪能看见 | 怎么验（可现场操作） |
|---|---|---|
| **无据不作答** | 问答页 | 问「儿科哮喘随访怎么做」→ 回「随访规范中未查询到相关内容」，且无引用 |
| **引用可回溯** | 回答下方来源卡片 | 点开卡片看到制度原文片段＋文档名＋切片序号；不是"根据某某规范"一句空话 |
| **引用不串号** | 多文档问题 | 问「冠心病和骨科节点有什么不一样」→ 两个 [n] 分别指向两份文档 |
| **写操作止步草稿** | 待确认卡片 + 质控报表 | 让它建随访 → 出卡片；此时报表草稿数**不变**；点确认后才 +1 |
| **规则由代码算，不由模型算** | `/docs` 接口 + 审计回放 | `check_followup_rule` 的 `passed` 来自规则引擎；模型只能读结果 |
| **全程留痕** | 后台 → 对话审计 | 每轮：决策类型、工具名、参数（住院号已脱敏）、耗时、结果摘要 |
| **数据在库里** | 后台 → 患者目录 | 表里 4 条演示患者，来源标"演示"；管理员新增一条，问答端立刻能查到；停用后立刻查不到 |
| **角色分离** | 后台 → 用户与授权 | 注册只能注册成医护；管理员身份只能在后台授予；系统始终保留至少一名可用管理员 |
| **可质控** | 后台 → 质控报表 → 导出 CSV | 无引用率、草稿确认率、工具调用分布，Excel 直接打开（带 BOM） |
| **接口可信** | `/docs` | OpenAPI 全量列出，可在线试调；`/health` 暴露 provider/db/embedding 维度 |

**当前实测数字**（2026-11-05）：14 张表 / 4 位演示患者 / 3 篇已发布制度（12 个切片）/
4 个账号（2 管理员 + 2 医护）/ 29 段 99 条断言全绿。

## 三、为什么不只是"套壳聊天"

1. **工具返回的是事实，不是结论。** 查患者只返回库里那一行；查制度只返回条文原文；合规与否由 `rules.py` 算。模型说的每句话要么来自工具返回，要么就是它编的——审计表能分清。
2. **两道闸门。** 制度校验通过才发票（HMAC + 5 分钟 + 一次性），票据才能生成草稿；草稿必须人点确认才落库。模型没有"直接写库"的路。
3. **引用是结构化的。** `[n]` 与检索结果一一对应，越界编号会被删掉并留痕；没写编号的回答打 `uncited_answer` 标记进报表，质控能查到"哪条回答没依据"。
4. **可回放。** 每一次运行有 `run_uid`，逐轮决策日志可回放——出了问题能查"它当时看到了什么"，而不是只能看最终回答。

## 四、明确不承诺的五件事（写在这里，比藏起来更可信）

| 不做/没做 | 影响 | 计划 |
|---|---|---|
| **没有真实患者数据** | 库里是演示患者，字段与 HIS 对齐 | 接 EMPI/HIS 同步任务，`patients` 表换成同步写入即可，上层不改 |
| **没接院内通知** | 红旗升级只生成工单号，不发短信/企微 | 接院内消息网关（表结构已留） |
| **规则只覆盖两种病种** | 骨科（含关节置换）、冠心病；其他病种会走通用校验 | 按病种补规则表，属数据配置不是改代码 |
| **模型会犯错** | 偶发不写引用、把问题答宽 | 已有拦截与打标；定稿仍需人看。这是医疗 AI 的常态，不是本项目独有 |
| **不能直接上生产** | 上线清单 5 项安全阻断未修：默认 JWT 密钥、零限流、Cookie 未强制 Secure、日志无保留策略、未做恢复演练 | 见 `docs/go-live-checklist.md`，属于上线前置动作 |

## 五、对着不同的人，说不同的一句话

- **对医务处**：「它是制度的口径统一器。制度怎么写它就怎么答，没写的直接说查不到；每条都能点回原文，谁改过制度、谁问过什么都有记录。」
- **对信息科**：「FastAPI + SQLAlchemy + Alembic，14 张表 5 个迁移，`/docs` 全量接口；部署一个进程，SQLite 起步，换 PG 只改连接串。冒烟 99 条断言可以挂 CI。」
- **对评审/专家**：「三个不变量：无据不作答、写操作止步草稿、全程可审计。三道实现：结构化引用、票据闸门、逐轮决策日志。证据都能现场点开。」
- **对合作方**：「MVP 已跑通，缺的是数据接入和上线加固，不是核心链路。这也是我们下一步要投入的地方。」
